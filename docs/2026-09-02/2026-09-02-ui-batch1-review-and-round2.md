## §3 第二輪修改需求（R2）

### R2-1【高】「我的緊急停止」授權開放帳號本人（D-1）

- 現況：`orders.py` toggle_kill_switch 對**兩種 scope 一律** `role != "admin"` → 403；
  risk.html 對非 admin 整包 readonly——非 admin 交易者完全沒有自我煞車可用。
- 驗收：
  - [ ] `scope=self`：帳號本人（owner）即可啟動／解除自己的急停；server 端強制，非 UI 隱藏。
  - [ ] `scope=global`：維持 admin-only。
  - [ ] 風控頁：非 admin 也看得到並可操作「我的緊急停止」；全站那塊對非 admin 唯讀。
  - [ ] 卡片說明文字「授權維持僅管理員可操作」同步改寫（只描述全站）。

### R2-2【高】冷靜期解除規則改為反悔窗（D-2）

- 現況：自己不能解、admin 可提前解（`/admin/cooling-off`）；文案多處寫「只有管理員能提前解除」。
- 驗收：
  - [ ] 啟動後 **5 分鐘內**：冷靜期卡片顯示「取消冷靜期」（化解誤觸），倒數或到期時間可見。
  - [ ] 逾時後：**無任何解除路徑**（admin 亦不可）；admin 冷靜期頁改為唯讀查看或移除。
  - [ ] 所有文案同步：「啟動 5 分鐘內可取消；逾時後任何人都無法提前解除，只能等到期」。
  - [ ] 啟動確認（hx-confirm）內容同步改寫。

### R2-3【高】冷靜期時長改「固定選項＋自訂」

- F1 原構想即固定時長（使用者當初指定），現行只有自訂 datetime。
- 驗收：
  - [ ] 提供快捷：**1 小時／1 天／1 週**＋自訂（保留 flatpickr）；上限 90 天維持。
  - [ ] 快捷以「現在＋時長」換算到期時間，選後仍顯示實際到期時間供確認。

### R2-4【高】Agent Token 區塊搬到帳戶設定頁（D-4）

### R2-9【新功能・可單獨排期】部位對帳檢查（系統帳 vs 券商實際）

> ⚠ 本項規模明顯大於 R2-1～R2-8（有實質後端工作），列在這裡是因為它源於本輪的查證發現。
> 可獨立排期，不必跟其他 R2 綁在一起。

#### 查證發現（本輪確認，取代先前「待工程實測」的假設）

我們原本把「Shioaji 會不會推送場外委託的回報」列為待實測。**你們自己的程式碼註解已經回答了**——
`inbox_worker.py` 的 N1 註解寫著：「永不可解的孤兒 association_pending 列（**如券商官方 App
下的單，對應委託永遠不存在**）」。也就是說回報**會**送達，但因比對不到 Order 而永久隔離。

四種紀錄逐一確認後的完整圖像：

| 紀錄 | 來源 | 場外單（手機 App／直連）會進來嗎 |
|---|---|---|
| 委託 | 只有本系統 `place()` 建 `Order` | ❌ |
| 成交 | 必須以 ordno／broker_order_id 比對到既有 Order | ❌（隔離） |
| 未平倉 | `BrokerPosition`，只由已比對成功的成交累加 | ❌ |
| 已平倉 | round-trip 完成回寫 `Trade(source="shioaji")` | ❌ |

`positions_snapshot` 明寫「純讀 DB，不呼叫 native API——BrokerPosition 是唯一真相來源」，
系統**從不詢問券商實際持倉**。定期 reconcile 也救不了（它撈的是「我們自己的委託」的進展，
撈回來仍要比對得到 Order）。

#### 問題：006 上線後會出現自相矛盾的畫面

006 的下單頁精簡條裡，**可動用保證金取自券商 API（真實值，含場外部位佔用的保證金）**，
而**未平倉取自系統帳**。場外開一口之後，同一條精簡條會顯示
「可動用保證金少了一大截、但未平倉 0 口」——兩個數字互相矛盾，看起來像 bug。
這在 006 上線後必然發生，不是假想情境。

#### 期望行為（= 驗收條件）

- [ ] 定期（建議與既有 watchdog／reconcile 同節奏，不新增輪詢）取券商**實際持倉**，
      與 `BrokerPosition` 比對。
- [ ] 不一致時，在**下單頁與風險控管頁**顯著提示，內容需具體：
      「券商實際 多 1 口，本系統未記錄」而不是一句「帳目不符」。
- [ ] **只提示、不擋單**（使用者 2026-09-02 定案）——不符的原因很多（場外單、回報延遲、
      對帳瞬間差），直接鎖住交易的風險更高。
- [ ] 提示需說明處理方式：場外開的倉**只能回場外平**（本系統的「平倉口數 ≤ 系統持倉」
      驗證會擋下在此平場外倉）。
- [ ] 比對失敗／取不到券商持倉時，顯示「無法對帳」而非「一致」——不可把未知當正常。

#### 不要動到的部分

- **`BrokerPosition` 仍是下單與風控的唯一真相來源**，本項只做「比對與提示」，
  **絕不可**用券商快照去覆寫或補寫系統部位（那會讓場外單悄悄變成系統部位，
  破壞既有的隔離設計，也會讓風控額度失真）。
- 隔離（quarantine）機制不變；R2-8 提到的隔離計數提示可與本項的提示合併呈現。

#### 為什麼值得做

它同時服務三件事：揭露場外交易（呼應「只在 quanquant 下單」的紀律）、
抓出 **agent 斷線期間的漏接**（這是靜默的資料缺口，目前完全沒有偵測）、
以及解釋上面那個「保證金與部位打架」的畫面。

  - [ ] 套用於所有有 mode 分頁的頁面：交易績效、委託、成交、未平倉（006／008 新頁一併）。
  - [ ] 與買／賣開關視覺同源，但**不使用漲跌方向色**（mode 不是價格方向，用中性選中色即可）。
