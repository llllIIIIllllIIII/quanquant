## 002 — 下單頁要能即時看到現價，並與「商品」欄位連動

**狀態**：已確認（使用者 2026-08-28 選定 **B 版**），待工程師實作　**優先**：高　**提出日期**：2026-08-28

### 使用者怎麼說

> 下單頁看不到任何報價這點確實是挺不方便的。我想到的是儀表板本身就有跟現價產生連動的介面，
> 所以立即顯示價格在下單頁面，這件事是可以參考他的呈現方式的。
> 不過本身下單頁面的可以顯示範圍跟儀表板的頁面可以顯示的範圍不同，
> 然後也需要考慮到與「商品」這個選擇欄位的連動性。

### 現況

1. 下單頁沒有任何價格資訊。要掛限價單必須另開儀表板看價、記住數字、再切回來輸入。
2. 儀表板已有現成的即時報價元件可以參考／重用：
   - 片段：`templates/partials/quote.html`（現價、漲跌、量／高／低、盤別、資料時間，價格漲跌色已走 `--rise/--fall`）
   - 端點：`GET /quote`（首載）＋ `GET /quote/stream`（SSE 推播，價格有變動才帶 `flash` 做閃爍）
   - 版面：`templates/dashboard.html:3-8` 的 `.quote-panel`
3. **這兩個端點目前是「單一商品」的**：`routers/dashboard.py` 的 `quote_now` / `quote_stream` 直接讀
   `poller.last`，**完全不接受 symbol 參數**；`QuotePoller` 也只輪詢設定檔裡的那一檔。
   同時下單頁的「商品」下拉是寫死的 `symbols: ["TXF"]`（`routers/orders.py`），
   而下單白名單另有設定 `order_symbol_whitelist`（預設 `TXF`）——三處各自為政。

### 期望行為（= 驗收條件）

- [ ] 下單頁在**表單上方**即時顯示所選商品的現價、漲跌（含百分比）與資料時間，沿用儀表板同一套視覺語言。
- [ ] 這條報價列比儀表板的**更精簡**（下單頁的垂直空間要留給表單與委託列表），
      並且在**捲動到委託／部位列表時仍然看得到價格**。
- [ ] 價格漲跌色跟隨使用者的漲跌配色偏好（與 001 同一套 `--rise/--fall`）。
- [ ] **報價必須跟著「商品」欄位走**：切換商品時，報價列要換成該商品的報價。
- [ ] **若所選商品沒有報價來源，必須明確顯示「無報價」**，
      絕對不可以繼續顯示上一檔／其他商品的價格——
      「看著 A 商品的價格下 B 商品的單」比完全沒有報價更危險。
- [ ] 報價停滯／休市／疑似臨時休市的既有狀態提示（`market-banner`）在下單頁一樣要看得到。
- [ ] 手機版不因為這條報價列而把表單擠出畫面。

### 不要動到的部分

- 報價的資料來源與輪詢節奏（TAIFEX MIS 每 5 秒、`QuotePoller`、freshness/halt 判定）維持現狀，這一項只談呈現與綁定。
- 不要為了下單頁另外新增一條輪詢或第二個 poller；沿用既有的 `/quote` + `/quote/stream`。
- `partials/quote.html` 若要改，請用「加 class / 加狀態」的方式，不要改動儀表板現有的欄位與版面。

### 本機參考實作（僅供效果驗證，不需照抄）

| 檔案 | 做了什麼 |
|---|---|
| `templates/orders.html` | 標題下方加一段 `.quote-panel.quote-compact`，內容直接重用 `/quote` + `/quote/stream` + `partials/quote.html`；「商品」下拉加上 `id="order-symbol"`。 |
| `static/app.css` | 新增 `.quote-compact`：縮小 padding／字級（現價 1.75rem → 1.4rem），並 `position: sticky` 吸在 topnav 下方；手機（<768px）改回一般區塊不吸附。 |

實作重點：

- 報價區用 `hx-get="/quote" hx-include="#order-symbol"` + `hx-trigger="load, change from:#order-symbol"`，
  **切換商品時會帶著當下選取的 symbol 重抓**（不是寫死第一個商品）。後端補上 symbol 參數即可生效。

### 給工程師的實作提示（重要）

1. **`/quote` 與 `/quote/stream` 需要 symbol-scoped 化**，這是本項唯一的後端工作：
   - `GET /quote?symbol=TXF` 回該商品的片段；未知／無來源的 symbol 回「無報價」狀態，不要回別檔的價。
   - SSE `/quote/stream?symbol=TXF` 只推該商品；**注意 htmx 的 SSE 擴充不會因為屬性變動就重連**，
     切換商品時要主動重建連線（例如把整個 `sse-connect` 容器換掉，或改用 `hx-on` 手動重連）。
   - 在只有單一商品的現況下，這件事可以先只做「參數收下並驗證」，行為不變。
2. **三處商品清單建議收斂成同一個來源**：`routers/orders.py` 寫死的 `["TXF"]`、
   `order_symbol_whitelist` 設定、以及 poller 追蹤的商品。否則多商品時很容易出現
   「可以下單但沒報價」或「有報價但不能下單」的組合。
3. 精簡版報價列**建議做成 `partials/quote.html` 的 class 變體**（像本機這樣加 `.quote-compact` 外層），
   而不是複製一份片段——否則之後改報價欄位要改兩個地方。
4. 尚未提出、先不做的後續：點價格直接帶入「價格」欄位、加減一檔按鈕、五檔買賣報價。

### 命名邏輯（本項的核心結論）

顯示名拆成三層，**各有各的用途，不可互相取代**：

| 層 | 例 | 用途 |
|---|---|---|
| 商品代碼 | `TXF` / `MXF` / `TMF` | 系統內部、API、**送單標的的唯一依據**。畫面上不可省略。 |
| 中文品名簡稱 | 台指 / 小台 / 微台 | 人看的辨識，對應交易者口語。 |
| 期別 | 近（目前恆為近月）／次／季／具體月份 | 指出是哪一個契約。 |

**顯示名 = 品名 + 期別（+ 契約月）** → `台指近 2609`

「近」目前是正確且穩定的說法，有程式面的依據：`sources/taifex.py` 的 `_select_nearest_contract`
一律挑**最近到期**的合約（且會依日盤／夜盤選 `-F`／`-M`）。也就是說系統顯示與送出的本來就
永遠是近月，稱「台指近」名實相符。

但也因為換月是自動發生的，**契約月必須看得見**：換月當天標的其實已經換過一次，
畫面上若只有「台指近」，使用者不會察覺。

### 時段（日盤／夜盤／全日盤）要不要進名稱？

使用者提問：券商慣稱有「台指近全」（全時段），我們是不是也該叫「台指近全」？

**結論：分開處理，規則是「名稱裡只放使用者能選的維度；不能選的維度用狀態顯示」。**

| 位置 | 顯示名 | 理由 |
|---|---|---|
| 下單頁 | `台指近`（**不加「全」**） | 下單標的就是近月這一個契約，日盤／夜盤是交易時段、不是不同標的。加「全」會暗示還有「台指近日」可選，但實際上沒有這個選項。時段狀態已由報價列右側的即時盤別徽章（● 日盤／夜盤）表達。 |
| 儀表板 K 線 | `台指近全` / `台指近日` / `台指近夜` | 這裡的時段**是使用者可選的**（圖表時段選單：全部／只日盤／只夜盤，預設全部），後綴要跟著選擇變。 |

佐證：`sources/taifex.py::_select_nearest_contract` 會依當下時段自動選日盤（`-F`）或夜盤（`-M`）
序列，因此我們的報價本來就是全時段涵蓋；而 `static/chart.js` 的 `sessions` 已有
`all / day / night` 三個選項、預設 `all`。

本機參考實作：`dashboard.html` 的圖表標題改為 Alpine `x-text`，後綴跟著 `session` 變動
（`all→全`、`day→日`、`night→夜`）；下單頁維持 `台指近`。

### 契約月（`2609`）該不該顯示？

使用者提問：旁邊的 `2609` 是否多此一舉？

**結論：目前必須保留，但理由不是「提醒行情跳空」，而是資料模型的缺口（見附錄 A 第 7 點）。**

- `broker/types.py::Position` 與 `db/models.py::Order`、`BrokerPosition` **都只有 `symbol`，沒有契約月**。
- 部位的唯一鍵是 `(user, broker, account, mode, symbol, direction)` —— 換月後在新契約下的單，
  系統會與舊契約的部位**當成同一個部位淨額計算**，但券商端是兩個不同契約、不會互相平倉。
- 在資料模型補上契約月之前，畫面上的契約月是**唯一能讓人察覺換月的線索**。

**使用者決定：不在報價列顯示契約月**，顯示名維持 `台指近`。換月的察覺不由這條報價列負責。

換月的察覺由其他機制負責，不屬於這條報價列的職責。

### 各顯示位置的定案

| 位置 | 顯示 | 決定理由 |
|---|---|---|
| 報價列（下單頁） | `TXF ▾ ｜ 台指近 ｜ 46,310` | 代碼在選擇器、中文名在旁邊 |
| 商品下拉（收合） | 只有代碼 `TXF` | 保持緊湊，且與旁邊的中文名不重複 |
| 商品下拉（展開） | 中文名為群組標題、代碼為選項 | 不熟代碼的人不用背；**用原生 `<optgroup>` 達成，不需要自訂下拉元件** |
| 委託列表／部位表的「商品」欄 | **維持代碼** | 欄位窄、對帳一律以代碼為準；中文名在上方報價列已出現過 |
| 儀表板圖表標題 | `台指近全／台指近日／台指近夜` | 跟著時段選單變（該處時段是使用者可選的維度） |

`<optgroup>` 的關鍵性質：**群組標題只在展開的清單中出現，收合狀態顯示的仍然只有 `<option>` 的文字**。
因此「展開看中文名、收合只看代碼」不需要自訂元件——鍵盤操作、螢幕閱讀器、手機的原生選單全部保留。
（自訂下拉的成本不在載入量，而在要自己重做這三件事，尤其手機的原生選單體驗無法複製。）

未來若同一商品要選不同契約月，`<optgroup>` 會自然變成真正的分組（`台指近` → `TXF202609` / `TXF202512`），
語意比現在更貼切。
