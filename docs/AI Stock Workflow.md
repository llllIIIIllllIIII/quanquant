# **交易者工作流系統需求整理**

## **1\. 產品目標**

建立一套給交易者使用的工具，協助完成以下流程：

1. 即時更新價格資料  
2. 依照不同時間週期顯示與計算技術指標  
3. 設定技術分析條件與警示  
4. 紀錄交易進出場與績效  
5. 管理重要市場日期與提醒  
6. 篩選符合條件的交易標的  
7. 後續可擴充為自動化交易或量化策略測試系統

初期目標不是直接自動下單，而是先完成「資料、警示、交易日記、績效統計」的穩定測試。

---

## **2\. 資料更新需求**

### **2.1 價格資料更新頻率**

系統需要在盤中持續更新價格資料。

基本需求：

* 價格資料更新頻率：約每 5 秒一次  
* 實際抓取資料時間應低於 5 秒  
* 盤中不可停止更新  
* 若資料庫效能不足，可依照預算評估付費升級或改用更高效的資料架構

### **2.2 資料需支援多時間週期**

同一個商品的價格資料，需要能轉換成不同 K 線週期。

需要支援的週期包括：

* 1 分線  
* 5 分線  
* 10 分線  
* 15 分線  
* 20 分線  
* 30 分線  
* 60 分線  
* 4 小時線  
* 日線  
* 3 日線  
* 週線  
* 月線

同一個技術指標，需要能在不同週期下分別計算。

例如：

* 5 分線的均線  
* 15 分線的 RSI  
* 日線的 MACD  
* 週線的突破條件

工程上不能只存一組指標結果，而是要能依照「商品 \+ 時間週期 \+ 指標參數」分開計算與呈現。

基本需求價格資訊跟成交量資訊

---

## **3\. 交易日曆與提醒功能**

系統需要有交易日曆功能，整合市場重要日期與使用者自訂日期。

### **3.1 系統預設市場事件**

日曆中需要支援以下事件類型：

* 降息／升息公布日  
* 非農就業數據公布日  
* 除權息日  
* 股市休假日  
* 其他重要總經數據日期

### **3.2 使用者自訂事件**

使用者可以自行新增需要標記的日期。

每個事件至少包含：

* 日期  
* 時間，可選  
* 事件名稱  
* 事件類型  
* 備註  
* 提醒時間

### **3.3 提醒方式**

系統需要支援提醒功能。

可行方式包括：

* App 推播  
* LINE / Telegram / Discord 等通訊軟體提醒  
* Email，後續可選

需要有資料來源，可以找找看

---

## **4\. 交易日記與績效統計**

初期先做交易日記，不直接接交易 API。

### **4.1 交易紀錄欄位**

每筆交易至少需要紀錄：

* 商品名稱  
* 多單 / 空單  
* 開倉時間  
* 開倉價格  
* 平倉時間  
* 平倉價格  
* 停損價格  
* 停利策略  
* 部位大小  
* 手續費，可選  
* 損益  
* 備註  
* 標籤，例如：突破、回測、均線、消息面

### **4.2 績效統計**

系統需要能統計一段時間內的交易績效，例如：

* 總損益  
* 勝率  
* 平均獲利  
* 平均虧損  
* 最大單筆獲利  
* 最大單筆虧損  
* 最大回撤  
* 不同策略標籤的績效比較  
* 不同商品的績效比較

一鍵匯出

## **5\. 新聞爬蟲與摘要功能**

系統需要能自動抓取交易相關新聞。

### **5.1 新聞來源**

初期可先抓取客觀新聞資訊，例如：

* 財經新聞  
* 總經新聞  
* 個股新聞  
* 產業新聞  
* 重大公告

### **5.2 LLM / Agent 功能**

可使用 LLM 或 Agentic workflow 做以下事情：

* 自動抓新聞  
* 摘要新聞重點  
* 判斷新聞相關標的  
* 標記新聞類型  
* 推送給使用者

初期不需要讓 AI 直接做交易決策，只需要做資訊整理與提醒。

抓哪些資訊，Perpexity 下 prompt 、模組化，哪種產業、哪個話題（關鍵字搜尋，用LLM 去比對相對高的）

川普哥，爬他的 fund ，追蹤他下了哪些標的或是產業

## **6\. 技術分析警示系統**

系統需要能自動偵測多個技術指標，並在條件成立時提醒使用者。

### **6.1 指標計算邏輯**

每個指標都需要支援：

* 指標名稱  
* 商品  
* 時間週期  
* 參數  
* 計算結果  
* 條件判斷

例如：

商品：台指期  
週期：5 分線  
指標：MA20  
條件：收盤價 \> MA20  
提醒：成立時通知使用者

### **6.2 多週期指標**

同一個指標需要能套用在不同時間週期。

例如：

5 分線 RSI \< 30  
15 分線收盤價 \> MA20  
日線收盤價突破前高  
週線站上長期均線

### **6.3 警示條件**

使用者需要能設定條件，例如：

當 5 分線收盤價 \> MA20 時，發送提醒  
當 15 分線 RSI \< 30 且 60 分線趨勢向上時，發送提醒

提醒方式可與交易日曆共用：

* App 推播  
* Telegram 目前的優先選擇  
* Email，後續可選

---

## **7\. 開倉、平倉、停損與停利**

### **7.1 初期：手動紀錄交易**

初期不直接串接交易 API，而是讓使用者手動紀錄：

* 進場點位  
* 進場時間  
* 出場點位  
* 出場時間  
* 停損設定  
* 停利設定

目的是先測試系統穩定度與交易紀錄流程。

### **7.2 後續：串接交易 API**

當系統、策略與操作流程穩定後，可考慮串接交易 API，測試量化交易或半自動交易功能。

### **7.3 停損與移動停利**

開倉時需要可以設定停損點位。

停利部分希望支援移動停損模式，例如：

進場後若價格往有利方向移動，停損點也跟著移動。  
當價格回落碰到移動停損點時，視為出場。

系統需要能記錄每次停損 / 停利觸發條件與結果。

---

## **8\. No Code 指標編輯器**

希望系統後續提供 No Code 指標編輯功能，讓使用者可以自行建立與測試條件。

可參考 XQ 的量化積木概念。

### **8.1 基本需求**

使用者可以用選單或積木方式建立條件，例如：

連續 3 日 收盤價 \> 前一日收盤價

或：

收盤價 \< 20 日均線  
且  
成交量 \> 近 20 日平均成交量

### **8.2 條件組成元素**

條件應該可以由以下元素組成：

* 連續 / 單次  
* 天數或 K 棒數  
* 商品欄位，例如：開盤價、最高價、最低價、收盤價、成交量  
* 自訂指標  
* 比較符號，例如：\>、\<、\>=、\<=、=  
* 數值  
* AND / OR 條件  
* 均線或其他技術指標

---

## **9\. 選標的篩選器**

系統需要有一個標的篩選器，讓使用者從大量標的中找出符合條件的商品。

### **9.1 初始篩選條件**

使用者可以先用表格勾選：

* 產業類別  
* 商品類型  
* 近期價格行為  
* 成交量行為

例如：

連續 3 天上漲  
定義：每天收盤價都高於前一天收盤價

### **9.2 自訂技術條件**

使用者可以進一步建立自訂公式。

範例：

連續 \[3\] 日 \[自訂指標 1\] \> \[數值\]  
且  
\[收盤價\] \< \[20 日均線\]

其中中括號內的項目都需要可以選擇或編輯。

## **10\. MVP 優先順序建議**

### **第一階段：資料與基礎紀錄**

優先完成：

1. 價格資料每 5 秒更新  
2. 多時間週期 K 線資料  
3. 基礎技術指標計算  
4. 手動交易日記  
5. 基礎績效統計

### **第二階段：提醒與日曆**

接著完成：

1. 交易日曆  
2. 重要市場事件匯入  
3. 使用者自訂事件  
4. 通訊軟體 / App 提醒  
5. 技術指標警示

### **第三階段：篩選器與 No Code 編輯器**

再做：

1. 選標的篩選器  
2. 自訂條件編輯器  
3. No Code 指標積木  
4. 回測功能

### **第四階段：交易 API 與自動化**

最後才做：

1. 串接券商或交易所 API  
2. 自動下單  
3. 自動停損 / 停利  
4. 策略自動執行  
5. 量化交易測試

---

## **11\. 工程師需要注意的重點**

1. 交易資料不能只看單一時間週期  
   同一個商品需要支援多週期資料與多週期指標。  
2. 初期不要直接做自動下單  
   先做交易紀錄、資料穩定性與警示功能。  
3. 指標與條件需要模組化  
   未來使用者會想自由組合條件，所以一開始資料結構不要寫死。  
4. 提醒系統需要共用  
   交易日曆提醒、技術指標提醒、新聞提醒，最好共用同一套通知機制。  
5. No Code 編輯器可以後做  
   但資料結構需要先設計成未來可以支援自訂條件。  
6. 回測與自動交易是後期功能  
   不建議在 MVP 第一版就處理完整自動交易。
